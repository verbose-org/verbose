# Verbose Compiler (verbosec)

## Vision

Verbose is a language where:
- **the AI expresses its reasoning explicitly** — proofs, hints, dependencies, all declared
- **the human can audit it** — every block traces to a numbered intention line
- **the compiler verifies, never guesses** — proofs are checked against the AST, not trusted
- **the compiler exploits declarations for optimization** — not just safety, also performance

The identity is: **explicit + verified + optimized**. Without optimization, it's just Coq with better syntax. Without verification, it's just a transpiler. Both halves matter.

## Design Priorities

```
1. Verifiability     — every declaration is mechanically verifiable
2. Exploitability    — every declaration is USED (optimization, codegen, analysis)
3. Safety            — unproven code is rejected
4. Traceability      — intention -> IR -> binary always navigable
5. Readability       — auditable without blind spots
```

Key filter: if a declaration serves neither verification nor optimization, it doesn't belong in the IR. This prevents *false explicitation* (verbose noise that looks rigorous but isn't mechanically checked).

## Project structure (the GitHub org)

The project lives under the `verbose-org` GitHub organization. Two kinds of repos sit there, with deliberately different roles:

**`verbose-org/verbose`** (this repo) — the **canonical compiler + language** :
- `src/`: lexer, parser, AST, verifier, three backends (native, WASM, interpreter)
- `examples/`: worked examples that exercise specific features (1-3 rules each, demonstrating each Phase / slice)
- `examples/holdout/`: AI-as-source-author hold-out intents (kept separate from the few-shot)
- `tools/`: generator pipeline (`generate.py`, `generate_sdk.py`, `eval.py`) and benchmarking
- `docs/`: design lessons, generator pipeline operator reference, native designs
- `INTENT.md`: documented prose patterns the generator maps to language constructs
- `CLAUDE.md` (this file): the design journal — every architectural decision, every constraint, every "why we don't do X"
- `README.md`: the public-facing pitch and reasoning

This repo evolves the language. It is the source of truth.

**`verbose-org/verbose-<poc-name>`** (separate repos, planned) — **POCs that consume the language**:
- One repo per POC. First planned: `verbose-homelab-filter` (URL filter for homelab/family networks).
- Each POC is a real, deployable program written in Verbose. It includes the `.intent`, the `.verbose`, runtime config, and deployment glue (systemd unit, install script, README oriented at deployers, not language designers).
- POCs **consume** the language at whatever version is current — they don't fork it.
- POCs do **not** drive language features. If a POC needs something the language doesn't have, the discipline is:
  1. Note the gap (issue or memo on this repo)
  2. Workaround in the POC to ship the slice
  3. If the gap is bloquant, discuss adding the feature to the language **on its own merits**, not as a POC dependency
- POCs are time-boxed: 1-2 focused sessions to ship, then they stand on their own. They are NOT side-projects that grow indefinitely.

The split is structural: `verbose-org/verbose` is for the language; everything else demonstrates it. This keeps the language pure (no ad-hoc features for one specific use case) and lets POCs be honest demonstrations (they live or die by what the current language can do).

## Dev workflow (cidx + branch-protected main)

Both the canonical compiler repo and POC repos use **[cidx](https://github.com/cidx-org/cidx)** as the CI driver. `cidx.toml` declares the pipeline phases (security / code / test / build) and the same containers + commands run locally and in CI — no drift between developer machine and GitHub Actions runner.

Install cidx once:

```sh
go install github.com/cidx-org/cidx/cmd/cidx@v1.6.2
```

Then the standard developer loop:

```sh
cidx run security    # trivy + gitleaks + cargo-audit, container-based
cidx run ci          # full pipeline: security + code + test + build
cidx validate        # check cidx.toml for shape errors
cidx doctor          # validate environment (docker, git, config)
```

Note: cidx's stock Rust presets pin `dhi.io/rust:1.83-alpine3.21` (a private image). The override in `cidx.toml` points all five Rust containers at `docker.io/library/rust:alpine` so the pipeline runs on a clean public CI runner. If cidx upstream switches the default to a public image, this override can be removed.

Note: the GitHub Actions workflow (`.github/workflows/cidx.yml`) generated by `cidx generate github` writes a self-bootstrap step (`go build -o bin/cidx ./cmd/cidx`) that assumes cidx's own repo layout. Patched to `go install github.com/cidx-org/cidx/cmd/cidx@v1.6.2` so the workflow runs cleanly on an external project. Pin the cidx version explicitly so a surprise upstream change can't break the CI silently.

For day-to-day work on `main`-protected repos:

```sh
# Quick path when you have changes to land:
cidx pr create "feat: short description"   # creates feature branch + draft PR
# … iterate, commit-push-watch in one go:
cidx cpw -m "fix: address review feedback"
# When ready:
cidx pr ready
# After approval + green CI:
cidx pr merge
```

The discipline:

- For any repo in `verbose-org` whose `main` is branch-protected (cidx-style PR-only workflow), all changes flow through PRs. Verbose itself may or may not have protection on at any given time — check via `gh repo view verbose-org/verbose --json defaultBranchRef` before assuming.
- Local commits should land on a feature branch when the destination is protected. If you accidentally commit to local `main` while it's ahead of `origin/main`, the unblock pattern is: create a feature branch at `HEAD`, reset local `main` to `origin/main`, push the feature branch, open a PR.
- Use `cidx pr create` (the dogfood path) when starting fresh work, regardless of protection status — it builds the same habit on both kinds of repo.

## Language Features (current)

- Types: `number`, `bool`, `text`, `collection(Type)`, `Result(T, E)` (declared failure path), named types
- Field ranges: `amount : number [0, 1000000]`, `name : text [..64]` (max byte length; verifier carries the bound, native exploits it for compile-time buffer sizing). **Both kinds are ENFORCED at runtime on input fields**: a Number outside `[min, max]` and a Text longer than `[..N]` both `sys_exit(1)` at field-load, before the rule body runs. That is what makes the sizing exploitation sound — the emitter is trusting a fact, not an assertion. Fields with no declared range stay unclamped and take the runtime-sized path
- Expressions: arithmetic (+, -, *, /, %), comparisons (>, <, >=, <=, ==, !=), boolean (and, or, not)
- Control flow: `if condition then expr else expr` (nestable)
- Let bindings: `let tax = amount * rate / 100` (CSE)
- Rule calls: `important_invoice(i)` — rules can compose
- Quantifiers: `all(collection, var => predicate)`, `any(...)`
- Aggregation: `sum(coll, var => expr)`, `count(coll, var => pred)`, `min(...)`, `max(...)`
- Per-element: `map(coll, var => expr)` → collection(T), `filter(coll, var => pred)` → collection of same element type
- Result: `Ok(v)` / `Err(e)` constructors; `match_result(r, v => ok_body, e => err_body)` consumer with both arms explicit
- Record construction: `ConceptName { field: expr, field: expr, ... }` — typed constructor; verifier cross-checks field set + per-field types match the concept declaration
- Text composition: `concat(e1, e2, ...)` — variadic text builder, scalar args only (number → decimal, bool → true/false, text as-is); no operator overloading on `+`, each arg is explicit
- Text→number conversion: `parse_int(<text>)` — strict scan (optional `-`, then 1+ ASCII digits, then end-of-input); aborts the binary on any other shape (empty input, lone `-`, non-digit byte). Optimizer folds `parse_int("<literal>")` to `Number` at compile time; native runtime path handles `parse_int(read(<resource>))` and other BoundText sources via the same (ptr, len) shape used by Read / Fetch / Phase-2I lets
- Number absolute value: `abs(<number>)` — Number, branch-free inline (`cqo; xor rax, rdx; sub rax, rdx` — 5 bytes total). Doesn't panic on `i64::MIN` (the value stays at MIN; optimizer fold uses `wrapping_abs` for the same property). Composes anywhere a number expression appears. Motivating use case: time-window comparisons where the natural `now - ts < window` form silently passes future events because the subtraction goes negative — `abs(now - ts) < window` expresses the symmetric window correctly
- Bitwise primitives: `band(a, b)` / `bor(a, b)` / `bxor(a, b)` / `bnot(x)` / `shl(a, n)` / `shr(a, n)` — all Number in, Number out, operating on the 64-bit two's-complement bit pattern. Native emits one instruction each (`and`/`or`/`xor`/`not` on rax, `shl rax, cl` / `shr rax, cl`). **Both shifts are LOGICAL** — `shr` zero-fills, it does NOT replicate the sign bit, so `shr(-8, 1)` is `9223372036854775804`, not `-4`. Use `/` when arithmetic (rounding-toward-zero) division is what you mean. The shift **count is masked to 6 bits** (`n & 63`), matching x86's masking of `cl` for 64-bit operands: `shr(x, 64) == x` and `shr(x, 65) == shr(x, 1)` — no panic, no zeroing, no UB. Every backend implements exactly this: the interpreter casts through `u64` before `wrapping_shr`, and the Rust transpiler emits `wrapping_shl` / `(… as u64).wrapping_shr(…) as i64`. WASM refuses all six (no emitter arm; the computational port is mechanical but unwritten). Verifier type-checks both operands as Number. Optimizer does not constant-fold any of them yet — operands are always evaluated at runtime, even when both are literals
- **Primitive names are reserved.** A rule may not be NAMED after a built-in expression primitive. `parse_primary` special-cases 36 names in call position — the closed set is `parser.rs`'s `PRIMITIVE_CALL_NAMES` (`Err`, `Ok`, `abort_if`, `abs`, `all`, `any`, `arena_scope`, `band`, `bnot`, `bor`, `bxor`, `byte_at`, `concat`, `contains`, `count`, `ends_with`, `fetch`, `filter`, `fold`, `fold_bytes`, `json_escape`, `le32`, `le64`, `length`, `map`, `match_result`, `max`, `min`, `now_unix`, `parse_int`, `read`, `shl`, `shr`, `starts_with`, `substring`, `sum`) — so a rule with one of those names can never be called: the parser resolves the call site to the primitive before it ever reaches the generic `Expr::Call` fallback. Pre-refusal, `rule band(a, b)` verified clean and then every `band(a, b)` call site silently meant *bitwise and* — a different function, a different answer, no diagnostic anywhere; the arity-1 form was barely better, reporting `band requires exactly two arguments` about a primitive the author never mentioned. Both are the same defect (a name whose meaning silently changes) and both are now refused at the DECLARATION, where the name is. `PRIMITIVE_CALL_NAMES` is mechanically pinned to the parser by `primitive_call_names_matches_the_parser_chain`, which scrapes every `name == "…"` guard out of `parser.rs` and asserts set equality — so the refusal cannot drift behind the parser. gen0 mirrors the check as `prim_named_rules` over its own narrower `span_is_primitive` set (see the gaps table below). Surfaced by the bitwise arc: `examples/body_content_gate.verbose` had a handler rule named `filter`, renamed to `body_gate` (byte-identical binary, 2678 B); `native::tests::streaming_x86_divmod_logic` had a `rule band(a, b) logic: out = a and b` that started returning `6 & 9 == 0` instead of `1`, renamed to `bool_and`
- Text substring test: `contains(<haystack>, <needle>)` — bool, true iff `needle`'s bytes appear anywhere as a contiguous substring of `haystack`. Empty needle is always true; needle longer than haystack is false. Byte-exact (case-sensitive). Native: naive O(N*M) scan using `rep cmpsb` per candidate offset; verifier `max:` bounds make worst-case work statically known. Both args restricted to allocation-free shapes (literal / text input field / BoundText). Optimizer compile-time-folds `contains("<lit_a>", "<lit_b>")` to `Number(0|1)`
- Text slice: `substring(<text>, <start>, <end>)` — half-open byte slice, returns text. Semantics: bytes `[start, end)`, so `substring(s, 0, length(s))` reproduces `s` and `substring(s, k, k)` is the empty text. No allocation: the result is `(text_ptr + start, end - start)` — a pointer slice into the SAME buffer as the input. Lifetime of the slice equals the lifetime of the input buffer. Bounds enforced at runtime, fail-closed: `end > length(text)` → sys_exit(1), `start > end` → sys_exit(1) (which also catches negative start/end via unsigned reinterpretation). Native integrates substring as a first-class arg to every text-consuming primitive (`length`, `concat`, `starts_with` / `ends_with` / `contains`, `json_escape`, `parse_int`) via a shared `emit_substring_bounds_and_slice` helper that produces `(rax=slice_ptr, rdx=slice_len)`. Optimizer folds when all three args are literals with valid bounds. The first tokenizer primitive (extract a literal out of a source buffer at runtime offsets) — self-hosting target depends on this
- Byte read: `byte_at(<text>, <index>)` — read the byte at the given zero-based offset of the text, returning a Number in 0..256. Bounds enforced at runtime, fail-closed: `index >= length(text)` → sys_exit(1), and negative index falls under the same `jae` unsigned compare (cast to huge unsigned > length). Native emit: load text via `emit_starts_with_load_text` (accepts literal / text input field / BoundText / Call inline / substring), evaluate index, unsigned-compare against length, `movzx eax, byte [text_ptr + index]` for the byte load with implicit zero-extension. ~40 bytes per call site. Second tokenizer primitive after substring — a scanner reads `byte_at(source, i)` byte-by-byte to find token boundaries, then `substring(source, start, end)` extracts the lexeme. Self-hosting depends on both
- Text byte count: `length(<text>)` — Number, byte count of a text expression. Counts bytes (not characters): for ASCII this is the obvious answer; for multibyte UTF-8 the result is storage size, not visual length. Native dispatches: text input field → inline `emit_strlen` scan; BoundText (read / fetch / Phase-2I let) → load `len_slot` directly (zero scan because the prologue already counted the bytes); literal → optimizer folds to `Number` at compile time; `concat(<text-only args>)` → 8-byte stack accumulator, each arg's length recurses into the same dispatch and is added in (zero materialisation — bytes are never written, only counted); `Call(<callee>, [Ident(input)])` returning text → Phase 2G-shape inline (same input ident, no callee lets), recurses on `callee.logic.value`; `json_escape(<text>)` of a text input field or BoundText → one-pass byte scan that adds `count(escape-triggering bytes)` to the input length (native escapes 5 bytes: `"` `\` `\n` `\r` `\t`, each becoming 2 bytes — the rest pass through as 1), accumulator in r8, no buffer allocated. Number-typed args in `concat` (literal numbers, number fields, `now_unix()`, `parse_int`, `abs`, arithmetic) are refused with a clear message that names the offending arg — they'd need an itoa-width helper which is its own slice
- Text suffix test: `ends_with(<haystack>, <needle>)` — bool, true iff `haystack`'s bytes end with `needle`'s bytes. Symmetric of `starts_with`. Empty needle is always true; needle longer than haystack is false. Native: load both args, compute `haystack_ptr + (hay_len - needle_len)` as scan start, then `repe cmpsb` on `needle_len` bytes. Same allocation-free arg constraints as `starts_with` (literal / text input field / BoundText). Optimizer compile-time-folds `ends_with("<lit_a>", "<lit_b>")` to `Number(0|1)`. Use case: file-extension routing without regex
- Text prefix test: `starts_with(<haystack>, <needle>)` — bool, true iff `haystack`'s bytes begin with `needle`'s bytes. Empty needle is always true (standard convention); needle longer than haystack is false. Both args must be text-typed; native restricts each arg to allocation-free shapes (literal, text input field, BoundText: `read(<resource>)` / `fetch(<connection>, _)` / Phase-2I text let). Optimizer compile-time-folds `starts_with("<lit_a>", "<lit_b>")` to `Number(0|1)`. Composes naturally with HTTP service handlers for path-prefix routing without regex
- Binary scalar reductions: `min(a, b)` / `max(a, b)` — Number, branch-free `cmp + cmovl/cmovg` (11 bytes per op). Distinct from the unary fold forms `min(coll, var => expr)` / `max(coll, var => expr)`: parser disambiguates by lookahead — if the second argument is followed by `=>` it's the fold form, otherwise the binary form. Both arguments are evaluated in source order (left then right) and both must be Number-typed; verifier rejects mixed types. Composes with `parse_int(read(<resource>))` for runtime-tunable clamps without recompile (`max(parse_int(read(floor)), min(parse_int(read(ceiling)), x))`); fail-closed posture inherited end-to-end from `parse_int` + resource `on_read_error: abort`. Optimizer is conservative (no compile-time fold yet — both args evaluated at runtime even when both are number literals)
- System clock: `now_unix()` — current Unix-epoch seconds as a number. Sampled ONCE per rule invocation via `clock_gettime(CLOCK_REALTIME)`; every reference in the rule logic loads the same captured value from a dedicated rbp slot (mirror of `req.timestamp` in HTTP services). The synthetic name `now` MUST appear in the rule's `reads:` proof so auditors find every clock-touching rule with a single grep — same audit shape as `read(<resource>)`. Wired in `emit_record_loop_prologue` (Phase 0 / 2 / Result / Record output rules), `emit_fold_program` (Phase 4 number fold), `emit_text_fold_program` (Phase 5b text fold), `emit_collection_program` (Phase 3 map/filter), `emit_multi_fold_program` (Phase 6 quantifier desugar), and `emit_parallel_program` (parallel hint — parent samples ONCE before fork; both children inherit the captured seconds via fork's COW, preserving the "ONCE per rule invocation" invariant without any per-worker syscall). Every emitter now wires the timestamp; no remaining clock-rejecting code path
- Verifier type check: bidirectional shape check on logic — `Ok`/`Err` rejected outside `Result(...)` context; `Ok(x)`/`Err(e)` content checked against declared arms when inferable; top-level output type checked against declared; conservative on lambda/let-bound vars to avoid false positives
- General reduction: `fold(collection, initial, acc, var => body)`
- Proofs: purity (reads/calls), termination (bound, structural, decreasing, increasing)
- Hints: `vectorizable: "reason"`, `parallel: "reason"`, `cache_result: "reason"` (justification required, parser rejects bare form), `overflow: [min, max]` (bounds mechanically verified against interval arithmetic)
- Traceability: `@intention` (string), `@source` (file:line), `@layer: domain|application|interface` (optional, sealed-subgraph discipline)
- Modules: `use "stdlib/finance.verbose"`
- Reactions: declared side effects with trigger rules; effects today are `print` (to stdout) and `append_file "path" content` (to a file). Path is a string literal at parse time — dynamic paths are refused so the auditor reads every file the program can ever touch.
- String escapes: `\n`, `\t`, `\\`, `\"` — closed set, unknown escape is a lex error (no silent pass-through for typos).
- Three backends: interpreter (--run), Rust transpiler (--compile), native x86-64 (--native), WASM (--wasm)
- Input modes: argv (default), one-shot stdin (--stdin), streaming line-by-line (--stream)

## Writing .intent Prose

The recognized patterns that the AI maps reliably to Verbose constructs (e.g. "for each X, check Y" → `all`, "for each X, compute Y" → `map`, "total of Y over X" → `sum`, etc.) are published in `INTENT.md`. Future sessions should consult it before inventing a pattern, and extend it when a new pattern is agreed upon. `.intent` evolves freely by design, but only within what we have written down — otherwise every `.intent` file depends on improvisation.

## Separation of Concerns

The compiler (verbosec) NEVER generates code. It verifies and compiles. Code generation is the AI's job, done through a separate tool (not part of the compiler). This boundary is non-negotiable:

- **AI** (external, non-deterministic): reads .intent, generates .verbose with proofs and hints
- **verbosec** (internal, deterministic): verifies proofs against AST, compiles to binary

If they're mixed, the verification loses its value. The compiler's credibility comes from being independent of the generation process.

A dedicated intent-to-verbose generation tool is planned as a separate project/script.

## LLVM Strategy

LLVM is NOT the primary backend. Verbose emits machine code directly because:
1. LLVM IR can't express field ranges, overflow bounds, or optimization hints
2. The translation to LLVM IR loses the domain knowledge that makes Verbose unique
3. LLVM adds overhead (prologues, stack protectors, alignment) that Verbose proves unnecessary

LLVM may become an OPTIONAL fallback backend for platforms without a native emitter. But all architecture decisions must keep the direct-emission path viable and primary.

## Two Execution Modes, Two Security Profiles

Security is pillar #1. Each feature is judged by what attack surface it adds, not by whether it is "useful". Under that frame, the compiler exposes two execution modes — not one primary and one fallback, but **two modes with deliberately different surfaces**:

- **Native (small, auditable surface, actively growing)**: x86-64 machine code emitted directly. No libc, no allocator, no tagged values held across non-local control flow, no dynamic dispatch. Grows phase by phase as new constructs land, each extension reviewed against this list. Binaries stay small (500 B–2 KB) and auditable line by line. As of this writing the native path covers scalar rules, reactions with `append_file`, `Result(number|text, text)`, record outputs, text-typed input fields, and `match_result` in the pass-through shape (see the phase table below).
- **WASM (text-computation parity with native)**: same principles as native but on its own track. WASM today handles scalar rules: arithmetic, comparisons, logic, `if/then/else`, number `let`, `Call(callee, [Ident(input)])` (inlined; refused if callee has its own bindings), the binary scalar primitives `abs(x)` / `min(a, b)` / `max(a, b)` (slice W1, branchless via `select`), and the **full text computation surface** (slices W3a + W3b + W3c): `Type::Text` as input field (encoded as `(i32 ptr, i32 len)` params into the module's exported linear memory) and as output (multi-value `(i32, i32)` return), `Expr::Text` literals embedded in the data section starting at offset 1024 (the first 1 KiB stays reserved: bytes 0..16 for future allocator metadata, bytes 16..48 back the itoa scratch region), `concat(...)` of text and number args via a single-pass bump-allocated fill (allocator state lives in a function-local i32 reset on each rule entry, so returned (ptr, len) values are valid until the next call into the module), text-typed `let` bindings (parked in two i32 slots same shape as a text input field), the W3c text primitives `length(text)` (single i32 widened to i64), `starts_with` / `ends_with` / `contains` (inline branchless byte-compare loops with the validator-required `unreachable` after `end loop`; `contains` uses a 6-i32 scratch group that includes inner+outer counters), `parse_int(text)` (helper function with a strict scan + WASM `unreachable` trap on bad input — same fail-closed posture as native's sys_exit(1); handles `i64::MIN` correctly), and `json_escape(text)` (helper function with a 3-result return `(out_ptr, out_len, new_bump_ptr)` so the caller updates its bump pointer; supports `\"`, `\\`, `\n`, `\r`, `\t` plus `\u00XX` for control bytes). Two helper functions appear in the module's function section (after func 0 = rule): itoa (when concat has number args), parse_int (when used), json_escape (when used) — each gets its own type entry. The (ptr, len) ABI mirrors native's BoundText slot convention exactly, so an auditor reads either backend with the same mental model; the bound travels alongside the data and is never derived from a sentinel. Slice W4-Result (2026-05-05) lifts `Result(number, text)` and `Result(text, text)` outputs. ABI: a tagged tuple multi-value return. `Result(number, text)` lands as `(i32 tag, i64 ok_value, i32 err_ptr, i32 err_len)`; `Result(text, text)` as `(i32 tag, i32 ok_ptr, i32 ok_len, i32 err_ptr, i32 err_len)`. Tag is `0` for Ok, `1` for Err; the un-live arm's slots are placeholder zeros, since the contract is "tag picks the live payload" — the host MUST gate decoding on the tag, not trust un-live slots. The if/else inside a Result-typed rule body uses a multi-value WASM blocktype, encoded as a separate type-section entry `() -> (...result tuple...)` whose typeidx the `if` instruction references. Slice W4-MatchResult (2026-05-06) lifts `match_result(...)` at the rule-body top level. Strategy: inline the callee body via the same `emit_wasm_result_body` (callee shares the input concept, so its params double as the caller's), stash the resulting tagged tuple into per-rule locals, then dispatch on tag with a multi-value if/else. The Ok arm copies the stashed ok payload into a fresh local that's registered as a binding shadowing into a `clone()`-extended `binding_shapes` map; the outer ok_body's `Ident(ok_var)` lookups resolve through it. Same pattern for the Err arm with the err (ptr, len) pair. The bound vars cannot leak past the arm because each arm builds its own extended ctx — clone-on-shadow rather than mutate-and-restore. Locals reservation is layout-aware: NumberText shape adds 2 i64 (ok_stash, ok_var) + 5 i32 (tag, err_ptr+len stash, err_var ptr+len); TextText adds 9 i32 (tag, ok+err ptr+len stashes, ok+err ptr+len bindings). The blocktype typeidx introduced by W4-Result also serves the inner if/else dispatching on tag — no new type entry needed. Slice 1 scope: one match_result, top-level only (rejected if nested in if/Ok/Err); `Call(callee, [Ident(input)])` target shape; same input concept; callee has no let bindings; outer rule shape == callee shape. The first three rejections each carry a clear breadcrumb naming the slice and the constraint, pinned by `wasm_w4_match_result_rejects_callee_with_bindings` / `_cross_concept_callee` / `_nested`. Worked end-to-end via `examples/purchase.verbose::discounted_purchase` — Ok arm transforms (`amount * 90 / 100`), Err arm pass-through. Surfaced and pinned a real bug during this slice: `BinOp::GtEq` and `BinOp::LtEq` had SWAPPED opcodes (0x57=`le_s` and 0x55=`gt_s` instead of 0x59=`ge_s` and 0x57=`le_s`); never caught because no prior W1/W3 test ran a `>=`/`<=` rule whose result depended on the comparison. Fixed; pinned at runtime by `wasm_w1_runtime_gteq_lteq_round_trip`. Refused in W3b (workaround in parens): nested concat (use a `let` for the inner concat — text-let RHSes are now legal). Still refused: `Record` / `collection` outputs, `match_result`, `map`/`filter`/`fold`, quantifiers, `read` / `fetch` / reactions / services. Effects (reactions, services, fetch, read, fork) don't port directly — WASM has no syscalls; bringing them in needs a separate WASI vs host-imports design call. The remaining computational features port mechanically — the AST supports them, the emitter just hasn't been written. This asymmetry is known and deliberate: the security-sensitive target is the native ELF, and WASM's growth follows native once we have a stable convention to mirror.
- **Interpreter (rich surface)**: the full language — collections, `map`/`filter`/`fold`, all `Result` / `Record` / `match_result` compositions, `@layer`. Runs in a Rust binary that parses JSON and evaluates expressions. Wider surface than native (JSON parser, allocator) but **every expression is still verified by the same compiler** against the same proofs.

Both modes verify the same AST with the same proofs. A rule accepted by the compiler is safe under both modes; only the execution profile differs. Native's trustworthiness comes from careful accumulation — adding a construct is a deliberate commit, never a drive-by "it's missing". Forcing native to grow to "completeness" (full heap, tagged unions, etc.) would add a C-sized attack surface and defeat the point. When native rejects an expression today, the answer is either "add a phase for it under the evolution rules below" or "run it in the interpreter" — never "silently upgrade native to handle it".

### What native still rejects, and in which priority

- **Result(T, E) with non-scalar T other than Record** (e.g. `Result(collection, _)`) — each remaining shape needs its own calling convention. Decide shape by shape, never fabricate a "universal Result" that carries unnecessary machinery. `Result(Record, text)` lifted (2026-05-07): the Ok arm routes the constructor's fields through `emit_record_as_json` (one JSON line per record, same format as `output: Named(C)` rules); the Err arm stays text → stderr → exit 1. Slice scope (initial): Ok-arm inner is a direct `Concept { ... }` constructor — the rule body's outer if/else still wraps it normally. **Slice extension same day**: `if/else` is now legal INSIDE the Ok arm too, via `emit_ok_record_dispatch` (recursively handles `Record` and `If`; both branches converge on the common `jmp loop_top` after the dispatch). So `Ok(if cond then RecordA{...} else RecordB{...})` works, with two distinct concept-named record shapes selectable at runtime. Pinned by `native_result_record_if_inside_ok_runtime`.
- **Reductions with non-number, non-text output** — Phase 4 covers `output: number` with top-level fold, Phase 5a covers `output: text` per-record, Phase 5b covers `output: text` via fold (append-only body, two-pass sizing). Still refused: `output: Record` with fold-computed fields (needs multi-slot record accumulator), nested folds (acc-slot stack discipline), and non-append-only text fold bodies like `concat(X, acc)` (would force O(N²) memory regardless of strategy — workaround: reorganize into append-only form).
- **Collection-returning rule calls or collection-valued reduction targets** — `map`/`filter` and Phase 4's `fold` target must be a direct `Field(Ident(input), coll_field)`. Composing through an intermediate rule that returns a collection is not supported; the caller has to inline the collection source.
- **Nested `concat(...)` inside a Call arg with its own Call args** — Phase 2H-b unlocked `Call` as a concat argument (one level of pre-eval). The callee's body can itself be a concat, but that inner concat cannot have its own Call args (`is_nested=true` rejects them with a clear message). Two levels of pre-eval would need ad-hoc rbp slots for the outer's r11 across nested pre-evals. Workaround: flatten the composition into a single concat, or an intermediate helper rule.
- **`match_result` with cross-concept callees where the callee's fields are NOT a subset of the outer's** — `match_result` cross-concept (2026-05-06) lifts the same-concept restriction PROVIDED the callee's concept's fields are a subset of the outer's by name AND type. The native emitter validates the subset up-front in `emit_match_result_inlined` and aborts with a breadcrumb naming the missing field or the type mismatch (pinned by `native_cross_concept_match_rejects_missing_field` / `_type_mismatch`). The inlined callee body uses `callee.input_name` for its Field accesses; the existing `offsets` map (built from the outer's concept) resolves them since by contract every name the callee uses also lives in the outer. Worked end-to-end via `native_cross_concept_match_result_runtime`: outer takes Purchase{amount, age, name}, callee `validate_amount` takes AmountOnly{amount}, both arms exercised. **Still refused**: callee fields that aren't a subset (would need argument-passing through additional slots or a real callee frame).
- **Nested `match_result` deeper than the prologue's static walk** — Nested match_result (2026-05-06) lifts the single-quartet limit. The prologue runs `count_match_result_max_depth` over the rule body; reserves N quartets where N = max nesting depth (≥1). Each quartet is 32 bytes (4 × i64) deeper into the frame than the previous one, indexed by depth via `match_slots_at_depth`. The emitter chain (`emit_eval_result_expr` → `emit_match_result_inlined` → `emit_redirect_callee_leaves`) carries both the current `slots` (used by the current match) and a `next_slots` (slots for any nested match_result inside the outer arms; just the current shifted by 32 bytes). For non-nested rules N = 1 — byte-for-byte the same layout as before. exit_flag_slot moves past the last quartet, so its rbp offset is now `-(base + 4*N + 1)*8` instead of fixed `-(base+5)*8`. Worked end-to-end via `native_nested_match_result_runtime`: 2-deep chained validation `match_result(validate_amount(p), amt => match_result(validate_age(p), age => Ok(amt), e => Err(e)), e => Err(e))` exercises all three reachable arms (outer Err, outer-Ok-then-inner-Err, outer-Ok-then-inner-Ok). **Still refused**: nesting deeper than what the static walk discovers (a runtime-built match_result tree would mis-reserve; the AST is fully static so this stays purely a slice-budget concern).
- **VariantConstruct / MatchVariant text fields with concat or Call** — Slice 4c lifts the blanket text refusal but restricts text field expressions to allocation-free shapes (literal, input text field, BoundText, Read). Concat and Call in VariantConstruct text fields are refused — their stack-allocated buffers are freed before the arena entry is consumed. Workaround: use a text literal, input field, or `read(<resource>)`. No current workaround for concat-built text in variant fields (would need arena-local text storage, a later slice).
- **Concat-producing text let bindings in recursive callables** — Number lets and allocation-free text lets (field pass-through, BoundText) work. Concat in a text let RHS is refused because the stack buffer's lifetime doesn't survive across recursive frames. Workaround: use a text input field or `read(<resource>)` instead of building text at the let site.
- **Text return from recursive callables with text input** — The text-return ABI `(rax=ptr, rdx=len)` and the text-input ABI `(ptr, len in struct)` haven't been composed yet. A rule that takes text input AND returns text (e.g., `scan_lexeme(source, pos) → text`) would need both paths active. Workaround: return a number (position or length) and let the caller extract via `substring`.
- **Record constructor text fields in recursive calls: arbitrary expressions** — Only pass-through (`s.source`) and BoundText are supported. Arbitrary text expressions (concat, substring) in a Record constructor field for a recursive call are refused. Workaround: pass the text through unchanged and reconstruct at the callee.
- **Multi-concept `concept_group`** — Slice 4a.1 caps groups at one concept (`g.concepts.len() == 1`). Mutual type recursion across two concepts (e.g. `Expr` ↔ `Stmt`) needs a tag namespace + arena partitioning design and lands in B.4b. Refused with a breadcrumb naming the slice; verifier still accepts the declaration so the interpreter (`--run`) keeps working on multi-concept groups.
- **Multiple `concept_group`s in one program** — Slice 4a.1 caps at one group per program. Multi-group native lowering needs the recursion-across-arenas design and lands in B.4a-followup. Refused with a breadcrumb; same interpreter compatibility note as the multi-concept case.

### Register conventions across emitters

Emitters that span multiple syscalls or phases share a register layout. Adding a new cross-phase register use requires either claiming a currently-unused register or saving/restoring on the stack — do not casually reassign any of these without auditing every caller.

| Register | Used by | Introduced |
|---|---|---|
| `r12` | argc (read at `_start`) | Phase 0 |
| `r13` | argv base pointer | Phase 0 |
| `r14` | current record index inside the main loop | Phase 0 |
| `rbp` | field-slot frame base (fields + let bindings at `rbp - 8*(i+1)`) | Phase 0 |
| `r15` | (per-emitter role — one or the other, never both in the same binary): file descriptor from `open()` in reaction emitters (Phase 1A) / inner loop counter in collection emitters (Phase 3) | Phase 1A / 3 |
| `r10` | concat buffer base for later length calculation | Phase 1B |
| `rbx` | concat write pointer (advances as args are written) | Phase 1B |
| `r9`  | saved pre-allocation `rsp`, used by the dynamic-sized concat path to free the buffer via `mov rsp, r9` (Linux `write` takes only 3 args, so `r9` survives the syscall). Set only when at least one concat arg is a text field. | Phase 1B (text-field) |
| `r11` | arena_base — `lea r11, [rbp + arena_rbp_offset]` set once at the entry rule's prologue when the program declares a `concept_group`. Recomputable at any point from `rbp + arena_rbp_offset` (the offset is a compile-time constant), which is the failsafe when an intervening syscall has clobbered r11. Linux syscalls clobber rcx and r11 by ABI, so the per-record body's text-write / append_file / read / fetch syscalls all destroy r11 — slice 4a.2's VariantConstruct emit will either reload r11 from its lea expression before each arena access OR keep arena access strictly outside syscall-touching code paths. Slice 4a.1 sets up r11 unconditionally on group programs (the lea is harmless even when no VariantConstruct site reads from it); the load-bearing artifact in 4a.1 is the rbp-relative arena_rbp_offset, not the register value. | Phase B slice 4a.1 |

Dedicated rbp-relative slots:

| Slot | Used by | Introduced |
|---|---|---|
| field slots (`rbp - 8*(i+1)`) | input concept fields — Number via atoi, Text stores argv pointer | Phase 0 / Phase 2E |
| let-binding slots (`rbp - 8*(nfields + k + 1)`) | `let` bindings evaluated in source order | Phase 0 |
| `match_slot` at the bottom of the frame | `match_result`'s inlined-callee Ok-value binding (reserved unconditionally in `emit_result_program`) | Phase 2D |
| `node_count_slot` (8 B at the bottom of the frame, below now_unix when present) | `concept_group` runtime arena entry count. Initialized to 0 in the prologue; slice 4a.2+ will bump on each successful VariantConstruct. Only allocated when the program declares a group. | Phase B slice 4a.1 |
| arena (`max_nodes * entry_size` B below `node_count_slot`) | `concept_group` runtime arena storage. Entry = 1 tag byte + 8 bytes per payload field, padded to 8-byte alignment. Reserved unconditionally when a group is declared, written by slice 4a.2's VariantConstruct emit. | Phase B slice 4a.1 |

Registers *not* in this table (`r8`, `rcx`, `rdx`, `rsi`, `rdi`, `rax`) are ephemeral — emitters may clobber them freely within a single expression. Note that Linux syscalls clobber `rax`/`rcx`/`r11`; any state that must survive a syscall belongs in `r10` or `r12`–`r15`. Slice 4a.1's `r11` arena base is set BEFORE any syscall in the prologue and is RE-set at every prologue (rule-entry, not per-record), so the only emitter constraint introduced is "don't make a syscall between `lea r11, ...` and the first VariantConstruct site". The recursive call/ret path doesn't touch r11 because Verbose-emitted callables don't use it.

**Self-hosted emitter invariant (`examples/vexprparse.verbose`, service slice 5a).** The service accept loop it emits is **closed**: every branch tail is `e9 <negative>` and the trampoline contains **zero `e8` call bytes** — it never transfers control to any emitted proc. That is what makes the arena registers reusable inside it: `r14` (the node counter) has been clobbered by the S2 field-select since slice 2, and slice 5a claims `r15` (the mmap arena base) as the `open()` fd for the per-request `log:` block. Both are safe *only* because no proc ever runs from inside the loop. This breaks the day a service trampoline calls an emitted proc — at that point the log block's fd needs a real save/restore or its own slot. `rbx` is NOT available: it has been the parsed request-field pointer since slice 2 (`write(r13, rbx, r14)` is S4's body write), which is why the log block diverges from the reaction trampoline's rbx-as-fd convention and matches verbosec's `emit_append_file_call` (fd in r15) instead. The swap is byte-length-neutral (`mov r15,rax` = `mov rbx,rax` = 3 B; `mov rdi,r15` = `mov rdi,rbx` = 3 B), so every reaction sizing mirror transfers unchanged.

**Slice 5b's span capture — a LIVENESS window, not register freedom.** When a `log:` block's content names `req.method` / `req.path`, the emitter splices a 9-byte capture per field at tramp+258, immediately after the parse and **before** the handler's field-select (`method → (r10, r8)`, `path → (rbp, r9)`). The select collapses one endpoint pair **asymmetrically** — the method variant destroys `rbx` (path_end) — so "read the other field after the select" is not a general answer. Of the four registers used, **`r10` and `rbp` are genuinely free** in the accept loop; **`r8` and `r9` are not** — `r8` is the parse loop's byte scratch (dead only *after* the loop exits) and `r9` is the itoa's sign save (write-before-read, and every itoa sits *after* the capture). They are safe purely because the captured values only need to survive `[capture, log block)`. **The load-bearing consequence: the log block can never move later than immediately-after-the-select** — a post-response-write placement would read an itoa-clobbered `r9` and emit a garbage path. This binds S5c's `on_error` tail and any future post-response hook. Note that `rbp` is the *safest* of the four, not the riskiest: emitted procs `push rbp` / `pop rbp`, so a future tramp→proc call would preserve it — `r14`/`r15` are the casualties of the closed-loop invariant precisely because procs clobber them without saving. Do not generalize the invariant to `rbp`.

**gen0's node arena is a first-class budget, and running out of it does not look like running out of it.** `examples/vexprparse.verbose` declares `concept_group VExpr [max_depth: 4096, max_nodes: N]`, and N is what the Rust native emitter mmaps for gen0. Before the bitwise arc, N was 6 000 000 and gen0's self-compile was touching essentially ALL of it — measured peak RSS 633 440 KiB against a 624 MB arena, i.e. no headroom whatsoever, while the comment in the file still claimed a "~1.5M node" peak. Any slice that added rules tipped it over, and the symptom is thoroughly misleading: gen0 does not report exhaustion, it **exits 1 having already streamed a partial ELF to stdout** (~750 KB of the 2.6 MB it owed), because the emit is streaming and the arena bounds-check fires mid-walk. That reads like a verify refusal or a codegen bug, and — because what actually varies is how many AST nodes an addition costs — it appears to track the SHAPE of whatever you just wrote (one branch fine, three not; a record-marshalled call fatal; a 3200-byte dead literal fine). A shape bisect will produce a coherent, confident, wrong diagnosis. Raised to 8 000 000, leaving ~2M nodes (~25%) spare; the reservation is `MAP_NORESERVE`, so the extra 208 MB is virtual and only touched pages cost RAM. **When a slice that grows this file starts failing strangely, check `max_nodes` first.**

### Self-hosted compiler (gen0): known verification gaps

**How the text-`==` defect evaded every sweep, and why that lesson outlives the bug.** It was **correct on half the input space.** A stuck-`false` equality agrees with the right answer for every non-matching pair, and a differential harness that feeds arbitrary or placeholder inputs (the sweeps in this session fed `"ab"` to every text field) practically never generates a *matching* pair — so `clients`, `layers`, `alert`, `priv_failure`, `showcase`, `config`, `allowlist`, `access_check` and `sum_by_tag` were all scored as AGREEING, run after run. Measured pre-fix on the nine, with the rule under test hoisted to entry and a matching input constructed by hand: **9/9 wrong on the matching input, 9/9 right on the non-matching one.** Two harness lessons follow, both cheap and both now applied. First, **a differential over a boolean needs inputs from both sides of the predicate** — reading the literal out of the source and feeding it back is a three-line change that would have caught this the first day. Second, **fixtures are part of the differential**: `allowlist` and `access_check` compare against `read(<resource>)`, their resource files did not exist, both compilers therefore failed closed, and the harness recorded a match — an agreement that proves nothing about the code path it was supposed to exercise. The regression pin asserts BOTH arms for exactly this reason (a false-only assertion passes against a stuck-false emitter) and writes the resource fixture itself. Note also what did NOT catch it: gen0 compiles ITSELF correctly and always has, because vexprparse contains **not one text `==`** — it compares text through `byte_at` loops (`name_eq`, the whole `span_is_*` family), which are NUMBER equalities on individual bytes. A self-hosting fixed point is a strong signal about the paths the compiler's own source exercises, and silent about the ones it does not.

The `hints:` row is the newest and its history is the reason this table exists. Before it landed, gen0 did not skip the block — it **halted** on it, and (pre-PR #141) that halt was indistinguishable from EOF, so every rule after a `hints:`-carrying rule was **silently dropped from the emitted binary at exit 0**: `showcase` emitted 1 rule of 6, `business` 1 of 4, `generated` 1 of 3, `pricing` 1 of 2. Those files counted as corpus passes the whole time. The trade being made is therefore **a silent truncation replaced by a documented verification gap** — strictly better, but still a gap, and it belongs in writing rather than in the diff only. See the `span_is_hints` banner in `examples/vexprparse.verbose` for the per-check detail, and `self_hosted_parses_all_rules_past_a_trailing_hints_block` (`src/native.rs`) for the pin.

**verbosec's own bool EXIT CODE is inconsistent, and that is why gen0 cannot match it (2026-08-08).** Measured on `emit_write_string`'s seven call sites: only two of them — `emit_full_program` and `emit_self_recursive_program`, the standard scalar paths — follow the `false` write with `mov qword [rbp + exit_flag_slot], 1`, so the binary exits 1. The other five (`emit_vectorized_program`, `emit_fold_program`, `emit_multi_fold_program`, `emit_parallel_program`, `emit_collection_program`) exit 0 on both arms. Which emitter claims a rule is therefore what decides the exit code, and for the scalar-threshold shape that choice is made by the **`vectorizable` hint**. Concretely, on the same false result: `examples/invoices.verbose::important_invoice` (hinted → SIMD) prints `false` at **rc 0**, while `examples/alert.verbose::is_critical` (unhinted → `emit_full_program`) prints `false` at **rc 1**. Two files, same language construct, same answer, different exit codes.

gen0 **skips the hints block wholesale** (top row of this table), so it cannot see the input that decides this and cannot reliably match either posture. It keeps the number trampoline's `exit(0)`. The consequence, stated plainly: after the format fix, **every bool file agrees with verbosec on stdout for both arms, and the four whose test input yields FALSE under a non-SIMD emitter still differ on rc** (`clients`, `collections`, `layers`, `priv_failure` in the sweep below; `alert` joins them on a false-yielding input, `invoices` never does). Closing it means either teaching gen0 the hint — which imports a whole optimizer decision into the self-hosted compiler for an exit code — or making verbosec's seven bool sites agree with each other. **The second is the real fix**, and it is a change to verbosec's semantics, not to gen0's fidelity, so it was deliberately not folded into the formatting slice. `two_generation_gen0_formats_bool_outputs_as_true_false` pins the divergence in BOTH directions (`assert_eq!((got_rc, ref_rc), (Some(0), Some(1)))`) so neither side can drift silently while it stays open.

**The declared-bound checks are gated by ONE rule per kind, and that is the whole safety argument.** `num_bound_check_size` and `text_bound_check_size` decide "this field gets a runtime check"; the emit rules (`x86_num_bound_check`, `x86_text_bound_argv`, `x86_text_bound_stdin`) each gate on the corresponding SIZE rule rather than re-deriving the predicate. That is deliberate and it is the same discipline `entry_uses_stdin` enforces for the channel choice, for the same reason: a size walk and an emit walk that disagree about whether N bytes are present desync `p_filesz` and `src_base`, and then every `byte_at` in the emitted binary reads garbage — a failure that looks nothing like an off-by-N. The `ty` gate mirrors verbosec exactly (`emit_bounds_check` fires for `Type::Number` only, `emit_text_bound_check` for `Type::Text` only), which is why a `bool` field carrying a range is deliberately NOT checked. Two things the re-scan road has to get right and does: the discriminator is the first byte INSIDE the bracket (`.` ⇒ the text form, digit-or-`-` ⇒ the numeric form), which is load-bearing because `type_code_of_span` maps `bytes` to 0, the **same code as `number`** — without it a `bytes [..N]` field would be checked against a misparsed numeric range; and an unrecognised shape emits NO check rather than a wrong one. Known divergences, both benign: verbosec BOUNDS its text scan at `max + 1` bytes on the principle that the declaration says it never has to read further, while gen0 checks after the strlen its `rep movsb` needs anyway (same accept/reject verdict, different work on the rejecting path, and the kernel's `MAX_ARG_STRLEN` caps argv at 131072 regardless); and gen0 inlines its 12-byte house `exit(1)` at each site instead of routing to a shared end-of-binary label, which is free to do because gen0's emitted bytes are never byte-compared to verbosec's — only gen1 to gen0. Note also that for `ScanState.source` specifically the new check is *dead*: the stdin read loop already fail-closes at `r13 >= 4 MiB`, the same constant as the declared bound. It is the fields declared SMALLER than the region (`[..200000]`) that were unchecked, and are now checked.

**gen0's input channel is DERIVED from the field's declared bound, not assumed.** gen0 has two input trampolines — `x86_argv_marshal` (52 B per text field: strlen, `rep movsb` into the fixed region, push the packed span) and `x86_stdin_marshal` (a 55-byte read-to-EOF loop plus 13 B per text field). Which one it emits used to be decided by `field_list_has_text`: *any* text field in the entry concept routed the whole program to stdin. `docs/self-hosting-stdin-channel-design.md` chose that as "the simplest deterministic rule" to unblock the self-compile, and it was right for exactly one program — the self-compile — and a **silent wrong answer** for every other. verbosec's default channel is argv, so a program whose text field was meant to arrive on argv got a binary that compiled, ran, exited 0, and read an empty stdin instead: `length(h.data)` over an argv string returned 0, and `sha512_fold` returned digest byte 0 = 106 where verbosec and Python `hashlib` both return 207. The 52-byte argv text arm was unreachable dead code the whole time, which is why nothing caught it — and no corpus count can catch this class, because acceptance only means "exit 0 with an ELF written".

The rule is now: **a text field whose DECLARED bound exceeds Linux's `MAX_ARG_STRLEN` (131072 bytes) cannot be delivered through argv, so it — and only it — routes to stdin.** Everything else (bounded at or below 131072, or with no declared bound) keeps verbosec's default argv channel. That is a mechanical consequence of a declaration plus a kernel constant, not a convention: the channel is visible in the source, at the field. `entry_uses_stdin` is the single rule both walks call — `blob_end_off`'s `msize` (size) and `elf_program_src`'s marshal dispatch (emit) — so the two can never disagree about which trampoline is there; a split would desync `p_filesz` and `src_base` and every `byte_at` in the emitted binary would read garbage. The cost of the change is exactly `39k - 55` bytes for an entry concept with `k` text fields (+23 at k=2, -16 at k=1), and it moved 35 of the 80 accepted corpus binaries — precisely the 35 whose entry concept has a text field; the other 45 are byte-identical.

The load-bearing consequence for the self-compile: `ScanState.source` declared `text [..256]` while carrying 1.3 MB, a false declaration nothing ever checked. It now declares `[..4194304]` — the same constant as the `cmp r13, 0x400000` fail-closed guard the stdin trampoline emits — and that declaration is what keeps gen1 reading its program from stdin. Shrink it below 131072 and the self-compile silently switches to argv and stops working. Pinned by `two_generation_gen0_reads_argv_text_input_field` (`src/native.rs`), which asserts the argv pointer AND length from a gen0-emitted binary, asserts a `[..4194304]` field still reads stdin, and closes on the external oracle: gen0-compiled `sha512_fold` must return 207, the value `hashlib.sha512(b"").digest()[0]` gives.

First, **every one of the three was fixed by WIRING, not by new machinery** — the serializer or the write sequence already existed in a sibling emitter (`x86_json_record` for the record entry, the span-aware Err block for the Result payload, `x86_fold_arg` for the streamed field) and simply was not reached from the position that needed it. Check for an existing emitter before writing one. Second, **the useful discipline was splitting at the REPRESENTATION boundary**: implement what the representation genuinely supports, refuse the rest at verify time with zero bytes, and scope the refusal to what the ENTRY rule REACHES rather than what the file contains. That is what kept `enrich`/`order_intake`-shaped dead concat from being refused, and it is why the corpus moved 110 → 105 → 100 and then stopped.

The differential was re-run over all 100 accepted binaries (collections included via count-prefixed argv). Before the bool slice: **84 agree** on stdout + exit code, **11 diverge**, **1 signal**, 4 skipped as unencodable. **After it: 88 agree, 7 diverge, 1 signal, 4 skipped** — and the remaining 7 are three distinct, all pre-existing things:

- **4 are the bool EXIT CODE alone** (`clients`, `collections`, `layers`, `priv_failure`): stdout is now verbosec's exact bytes on both arms, and only rc differs, for the reason in the note above — verbosec itself is inconsistent and the deciding input is a hint gen0 skips. Note the agree/diverge split for bool files is **input-dependent**: the four that moved into `agree` (`alert`, `bonus`, `invoices`, `logs`) did so because the sweep's argv yields TRUE for them (rc 0 both sides); feed `alert` a false-yielding input and it joins the four. Only `invoices` agrees on both arms, because it is the one bool file carrying `vectorizable`.
- **2 are the apples-to-oranges reaction pair** (`audit_log`, `audit_simple`): gen0 emits the REACTION trampoline (which writes the log file and prints nothing) where `--run <bool rule>` makes verbosec emit the bool rule directly. Different programs, not a divergence.
- **1 is a harness artifact**, not a compiler divergence at all: `vexprparse`'s own entry `skip_spaces` declares `source : text [..4194304]`, so by the documented `entry_uses_stdin` rule gen0's binary reads STDIN while verbosec's default channel is argv; feeding the same argv to both compares different input channels, and the binary is correct on the channel its declaration names.

**No silent wrong answer remains in the sweep** — *and that sentence was true only of what the sweep could reach: the text-`==` defect was live in nine of these same binaries and scored as agreement, see the caveat below and the text-`==` row in the gaps table.* The 1 signal is still `retirement` (the `AstMap`-over-record-elements int3 placeholder — a collection-element marshalling hole, not a text-path miss), and `recursive_text_eval` is still the one accept-what-verbosec-refuses gap: verbosec refuses natively with `native input field 'node' has unsupported type (only number/text today)` while gen0 emits 2789 B that at least fails closed (rc 1, zero output). Both are unchanged and both remain open.

**One caveat the sweep's own numbers hide, and it is the more interesting finding.** `access_check` and `allowlist` sit in the `agree` bucket for a REASON THAT DOES NOT EXERCISE THE RULE: both `read(<resource>)` a file the sweep never creates, so both binaries fail closed (rc 1, empty stdout) and trivially match. Create the files and they diverge — **gen0 evaluates `<text field> == read(<resource>)` as FALSE unconditionally**. Measured with `/tmp/verbose_allowed_tag.txt` containing `ab`: `allowlist ab` → verbosec `true`, gen0 `false`; `allowlist zz` → both `false`. Same on `access_check` for `1 ab`, `2 ab ab` (verbosec `true`, gen0 `false`) and `2 ab zz` (both `false`). This is **pre-existing** — the pre-slice binaries printed `0` for every input, i.e. the same wrong boolean, just rendered as an integer — so the bool slice did not introduce it and does not fix it; it only made the wrong answer legible. It is a genuine silent-wrong-answer family that survived the "family is closed" sweep because a differential run without resource files present cannot see it. **Any future differential over gen0 must materialise declared resources before drawing conclusions.**

**CLOSED 2026-08-08, and the caveat above under-stated it by an order of magnitude.** The narrow symptom ("`<text field> == read(<resource>)` is false") was not a `read()` bug at all — `read()` works, and Number `==` works. The defect was **all text equality**: literal RHS, `read()` RHS, either operand order, `!=` too. Nine corpus files carried it, not two. The reason the caveat found only the two `read()` ones is the same reason the whole thing hid for so long — the other seven compare against a *literal*, the sweep feeds placeholder text, and a stuck-`false` equality is RIGHT on every non-matching input. See the text-`==` row in the gaps table for the root cause and the fix, and the paragraph after it for the two harness changes (both-arms inputs, and fixtures) that make this class visible. Post-fix differential over the 100, with resource fixtures created: **84 agree / 11 diverge / 1 signal / 4 skipped**, up from 81/14/1/4 on the same harness before the fix — the three that moved are `access_check`, `allowlist` and `sum_by_tag`, the only text-`==` files whose divergence a placeholder-input sweep could see. The other six were verified separately with hand-built matching inputs: 9/9 wrong before, 18/18 right after (both arms each).

**Three of the four never-run files are now run (2026-08-07), and one of them was a gap.** `hello_http` — the only accepted SERVICE program — was started and spoken to over TCP: gen0's binary answers `GET / HTTP/1.0` with bytes IDENTICAL to verbosec's 429-byte service binary (`HTTP/1.0 200 OK\r\nContent-Length: 29\r\n\r\nHello from Verbose over HTTP!`). `expr_stmt::eval_expr` and `callable_let_variant::depth` agree with verbosec EXACTLY, including the failure: both take a `concept_group`-typed input that argv cannot encode, and BOTH compilers emit a binary that SIGSEGVs on `depth 0` (rc 139 each) or prints `0` (`expr_stmt`, both rc 0). That is a shared verbosec/gen0 hole — a group-typed entry input has no argv marshalling in either backend — not a gen0 divergence, and it is the reason these files were never in a sweep. `recursive_text_eval` is the one real finding: verbosec REFUSES it natively (`native input field 'node' has unsupported type (only number/text today)`) while gen0 ACCEPTS and emits a 2789-byte binary — another accept-what-verbosec-refuses gap, though the binary at least fails closed (rc 1, zero output) rather than lying.

**A stale comment cost more than the feature did (2026-08-06, corpus 80 → 113).** 33 corpus files — essentially the whole crypto arc: `aes_*`, `sha256_*`, `ghash*`, `hmac_sha256`, `hkdf_*`, `x25519`, `p256_*`, `ed_*`, `sc_*` — were blocked on a **multi-line `if / then / else`**, the layout every one of them uses. Three banners in `examples/vexprparse.verbose` and the `Status:` line of `docs/indent-dedent-design.md` all said the blocker was that *"there is no INDENT/DEDENT in this tokenizer"*. That was false, and had been since brick 8b: `line_width`, `tokenize_indent`, a real `ColStack`, and `tok_kind` emitting `Newline = 600` / `Indent = 700` / `Dedent = 800` were all already there, along with `skip_seps` and `skip_seps_dedent`. The actual blocker was that the if-chain (`parse_primary`'s `isif` branch → `if_then` → `if_else`) peeked for `then` (207) and `else` (208) at the **raw** cursor: with a separator sitting there the peek saw 600/700, both rules took their tolerate-the-absence arm, and `parse_or` — handed a separator — returned `AstErr` consuming nothing, collapsing the parse. Routing those three peek positions through the already-existing `skip_seps` fixed it in six lines. The stale sentence had the slice scoped as a column-stack project; **the comment was the expensive artifact, not the code.** Zero files were lost and 79 of the 80 previously-accepted binaries are byte-identical (the 80th is `vexprparse` itself, whose source the six edits changed).

Two constraints on that fix are load-bearing and worth not re-litigating. First, separators are transparent **only** in the three if-keyword positions — this is deliberately *not* a general line-continuation rule, because verbosec REJECTS a newline inside a binary expression (`out = n.v +` ⏎ `1`), and making separators transparent everywhere would have gen0 accepting programs verbosec refuses, i.e. a new row in the gaps table above, in the wrong direction. Second, gen0's `skip_seps` has **no `depth` counter** where verbosec's `skip_if_separators` does, so it eats an Indent without ever pairing the matching Dedent. Measured benign across all 151 files (`parse_stmts` re-skips at every statement head; `skip_seps_dedent` absorbs strays at item level), but it costs one real layout: an Indent *between* `if` and its condition puts a Dedent immediately before `then`, which gen0 cannot cross — verbosec parses that, gen0 refuses it. Refusing what verbosec accepts is the safe direction, so the slice stops there rather than reach for `skip_seps_dedent` (which would swallow block-closing Dedents and re-open PR #141's silent-truncation hole). The remedy, when a real program needs it, is a `(cell, depth)` return from `skip_seps` threaded through `if_then → if_else → if_build`. All of this is pinned by `self_hosted_parses_multi_line_if_then_else` (`src/native.rs`), including the refusal — so the day the depth counter lands, that assertion flips and tells you to move the layout into the accepted set.

## Transpilation Strategy (rejected direction)

Rust/Go/other source → Verbose transpilation is **rejected** for the same reason as LLVM: the source does not contain Verbose's declarations (reads, overflow bounds, termination bound, intention). Any transpiler must either emit trivial proofs (losing all verification value and all hint-driven optimizations) or infer them (violating the zero-trust rule that proofs are declared, never guessed).

The healthier answers to "don't isolate from existing ecosystems" are:
1. **Binary interop** — Verbose emits ELF; other languages link via FFI.
2. **Assisted generation** — tooling that suggests a Verbose equivalent from foreign source, with proof slots filled by a human or AI (not by the compiler).
3. **Manual module bindings** — external functions imported through an explicit Verbose declaration stating the proofs on our side.

Rule: **if the proof is not declared, it does not exist**. No pipeline fabricates proofs.

Full rationale: README.md → "Why Not Transpile Rust/Go → Verbose?".

## Development Rules

- **Always explain what you're doing and why.** The creators are learning alongside the AI. Every change must be explained clearly.
- **No silent changes.** Explain what changed, why, and what impact it has.
- **Explain concepts when they arise.** Don't assume knowledge of compiler theory or Rust internals.
- **Zero external dependencies** — everything is hand-written.
- **Zero-trust verification** — the compiler verifies AI proofs, never trusts them.
- **All tests must pass** before any commit (`cargo test`).
- **Closed attributes** — unknown `@attributes` are rejected, not silently ignored.
- **No false explicitation** — every declaration must be mechanically verified or exploited. If it's just decoration, remove it.
- **The native backend is the destination** — the Rust transpiler is a fallback. Architectural decisions should keep the native path open.
- **Every feature must serve security, performance, or unique machine code.** No ergonomic sugar without optimization value.
- **All documentation in English.** The repo is international. **One scoped exception: `docs/learn/`.** Those are pedagogical articles (cross-posted to [arcker.org](https://arcker.org), the canonical home) written in French, pinned to a stated language version per article. They are blog content that happens to live in the repo, not compiler reference docs — they do not track the current codebase and are exempt from the English rule and the "keep up to date" expectation. Everything else under `docs/` (design notes, effect model, native designs, etc.) stays English and current.
- **Pop sub-agents for exploration-heavy work.** When mapping a refactor across many files, scanning for every touch point of a construct, or investigating a broad "where is X used" question, delegate to a sub-agent (`Agent` tool, `Explore` type for searches, `general-purpose` for mixed read+reasoning). The agent's summary lands in the main context; the raw file reads do not. Reserve the main context for actual edits and conversation with the human. Sub-agents are not a substitute for judgment — always read the code you're about to modify yourself, and verify the agent's claims against the file before acting on them.
